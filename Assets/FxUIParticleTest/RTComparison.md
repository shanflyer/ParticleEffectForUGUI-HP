# RT / UI 粒子分组对比场景

打开 Scenes/FxRTComparison.unity 并运行，层级在运行时生成。

## 负载与层级

控制界面主 Canvas → 20 个独立特效 Canvas（各附 CanvasGroup 和背景）→ 底部 UI / 粒子层 / 顶部 UI 三个同级节点。粒子层包含单个特效根及 4–6 个子粒子系统。每个特效独占一个 Canvas，按 4 列 × 5 行排列；加上控制界面主 Canvas，场景共 21 个 Canvas 组件。

共 20 个特效、98 个子粒子系统，是原先 10 个特效、49 个系统的两倍。10 种参数各出现两次，相同种类使用相同随机种子，以便测试网格共享。默认全部可见、正常播放。效果显示面积统一为 136×136 UI 单位。RT 和 UI 两种模式使用相同槽位、分组层级、发射参数、材质和种子。

当前使用加法粒子材质，无拖尾、Mask、滚动或动画面板。本场景新增了多 Canvas 和分组层级，但不能代表所有生产场景。特效 Canvas 没有 overrideSorting，不改变层级绘制顺序。

## RT 模式

20 台特效相机、20 张 RT，通过 RawImage 显示；另有一台共同屏幕相机。
分辨率依次为 128、256、512、1024、2048，默认 256。ARGB32 + 24 位深度，无 MSAA/MipMap/HDR。
20 张 2048 RT 的颜色和按 4 字节估算的深度约 640 MiB，不含 URP 临时资源与驱动占用；每帧有 20 台相机渲染，选择高分辨率会实际增加负载。

## UI 粒子开关（分别控制）

| 开关 | 实际行为 | 生效条件 / 对比限制 |
|---|---|---|
| 网格合并 | UIParticle.mergeRenderers | 合并兼容粒子系统，降低 Renderer/提交数量 |
| 组缓存 | UIParticle.useGroupCache | 缓存共享组查询；共享关闭时收益可能很小 |
| 烘焙降频 | UIParticle.bakeFPS = 30 / 0 | 30Hz 减少烘焙更新，但改变更新频率；不是等画质优化 |
| 裁剪 | UIParticle.earlyCull = 0 / 1 / 2 | 关 / 仅渲染裁剪 / 加入 alpha≈0 的模拟裁剪；全部可见时通常无收益 |
| 静态缓存 | UIParticle.staticMeshCache | 暂停且变换等状态未变化时生效；默认持续播放，不预期收益 |
| 网格共享 | UIParticle.meshSharing Auto / None | 两组相同特效种子和配置一致，可复用模拟与网格 |

另新增顶点色 Gamma 开关，同时设置主 Canvas 和每个特效 Canvas 的 vertexColorAlwaysGammaSpace；在 Linear 色彩空间且插件自动颜色校正开启时，可跳过 CPU 顶点色转换。Gamma 色彩空间下不预期这项收益。RT 模式中这些按钮明确标为“UI 模式预设”，不会宣称影响 RT 路径。采集时禁止修改配置，输出文件名包含每项配置。

## 采集

开始采集：重启当前模式，预热 5 秒，采样 30 秒。停止并保存可提前结束。
对比 RT → UI / UI → RT：依次自动采集两种模式，建议两个顺序都测试。
数据位于 Application.persistentDataPath/FxRTComparison/日期时间/，Console 输出完整路径。

逐帧 CSV 与 comparison.csv（均值/P95）包含：帧间隔、主线程/渲染线程时间、GC 分配、Unity 已用/保留内存、Draw Calls、Batches、SetPass、三角形、顶点、GPU 时间、存活粒子数和 RT 理论占用。
不支持的计数器记录 NaN；GPU 计时需要设备支持与 Frame Timing Stats。主线程和渲染线程时间可能含等待，不可相加。RT 理论估算不代表完整显存，也未测功耗或带宽。

目标 200 FPS、关闭 VSync；平台刷新率或模拟器仍可能限制实际 FPS。在帧率上限下应结合 CPU/GPU 耗时比较。关闭 Deep Profile 采集正式结果。分辨率和烘焙降频影响画质，比较时须记录。采集数组预分配；状态文字每 0.5 秒更新，两种模式相同；写盘在采集结束后。

本次改动完成真实 Unity 引用的离线 Player 编译检查，未运行 Unity/模拟器，尚无新版实测性能结果或画面验证。


## 每组 Canvas 的夹层

固定兄弟顺序为 `01_底部UI → 02_粒子层 → 03_顶部UI`。底部 UI 有底板和装饰，顶部 UI 有标题、不透明遮挡条及徽标，遮挡条实际穿过粒子显示区域。RT 模式把 RawImage 放到粒子层；UI 模式把 UIParticle 放到同一层。切换时只重建粒子层内容，不把粒子追加到顶部 UI 后面。两种模式使用完全相同的底部和顶部 UI，以覆盖 UI 与粒子交错绘制场景。


## 2026-09-10 增量采集与分组控制

- 目标帧率改为 200，VSync=0；离开组件时恢复进入前设置。目标值不保证 Android/模拟器能跑到 200。
- 分组 -1 / +1，默认 20，范围 0–100；每组独占一个 Canvas，包含底部 UI、粒子层和顶部 UI。0 组作为控制界面基线。数量变化时释放原相机/RT/特效，重建组层级；采集期间锁定分组。
- 自动调整网格和缩放以保持全部组在画面内。组数增加会改变每组屏幕覆盖面积，因此分组对比同时记录 layoutScale；不是固定每组像素面积的填充率基准。
- 文件名记录组数、RT 分辨率、全部优化开关、详细计时、Gamma。每轮 .meta.txt 记录系统数、布局缩放、屏幕、色彩空间等。
- 新增 CPU Main Thread Active Time 候选计数器、排除 VSync 的 CPU 计数器、GC 堆已用/保留、纹理/网格内存；只在计数器有效且有采样时输出。排除 VSync 不等于排除全部 GPU 等待。
- 新增 Time.realtimeSinceStartupAsDouble 计算的 wall_frame_ms，以及 FrameTiming 的 CPU 主线程、Present 等待和渲染线程时间。它们可能来自延迟帧，不做强行同帧相减，也不从主线程总时长推断纯 CPU 工作量。
- UIParticle 统计包含准备/模拟/烘焙/合并/提交耗时、Bake 尝试次数、烘焙顶点、SetMesh 次数、活跃 Renderer、粒子统计所属帧。耗时只有开启“详细计时”且样本有效才输出，否则 NaN；详细计时会有额外测量开销，正式基线默认关闭。
- 每帧 CSV 共 37 列，数组预分配；原有前 14 列保留。渲染线程或活跃时间候选计数器不支持时不会制造数值。
